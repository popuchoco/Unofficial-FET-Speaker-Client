# 開發里程碑

目標是在使用者自己的 Android 裝置上，讓小狐狸和小愛講能播放 AI 回覆及 KKBOX 音樂，並確認兩款音箱各自可使用的連線能力。App 使用系統音訊與供應商官方頁面，不依賴遠傳會員或專案後端。

| 階段 | 工作 | 驗收 |
| --- | --- | --- |
| 1．瀏覽器雛型 | 驗證官方 AI 與 KKBOX 入口、本機朗讀流程 | 可直接開啟雛型，朗讀與停止流程通過模擬測試 |
| 2．Android 首版 | 建立原生應用、Material 3 三種外觀、系統藍牙入口、本機朗讀與 BLE 診斷 | 完成編譯、Lint 和單元測試；開發期間不產出 APK。以 GitHub Actions 延續編譯與 Lint |
| 3．手機操作驗收 | 檢查啟動、外觀切換與持久化、官方入口、中文朗讀、藍牙權限拒絕與重新授權 | 在 Android 上逐項驗證。記錄 Android 版本、操作結果與重現步驟 |
| 4．兩款音箱相容性 | 分別驗證媒體輸出、斷線重連、BLE 廣播與 GATT 服務。再評估麥克風、按鍵與電量 | 記錄每款音箱的實測能力，依結果決定各項功能是否能支援 |
| 5．社群測試版 | 修正實機發現的問題，整理已驗證能力、安裝方式與版本變更 | 發佈前須具備可安裝產物、通過自動檢查，以及可供使用者比對的相容性紀錄 |

每完成一個里程碑就提交；同一大階段通過驗收後集中推送。階段 1–2 屬於首個可安裝的基線，階段 3–5 屬於實機驗收與社群測試版。實機功能以實際結果為準。

開發期間不產出 APK。實機項目及通過條件見[規格與改造範圍](scope.md)。

## 音箱觸發語音對話

目標流程為音箱觸發、手機收到事件、開始收音、取得 AI 回覆，再由音箱播出。先在兩款音箱確認喚醒或按鍵是否會透過 Android 媒體事件或 GATT 通知送達手機，並分別判斷音箱麥克風是否可作錄音輸入。「音箱按鍵診斷」可在前景開啟 30 秒測試，顯示 Android 實際送到 App 的媒體按鍵次數與最近代碼。BLE 診斷已能列出服務與特徵，並在裝置公開標準 Battery Service 時只讀 Battery Level。Android 可能把按鍵交給另一個媒體播放器，因此請先停止其他播放，無事件時記錄當時的手機狀態，並另測 BLE 與螢幕鎖定情境。

已加入首頁的手機端繁中離線語音輸入。ChatGPT 已接官方開源用戶端授權及 Responses API：使用者自行登入，問題由裝置直接送出，完整回答再以本機中文語音播放。需在支援離線辨識的 Android 12 以上裝置驗收麥克風授權、成功辨識、取消、無可用語言、背景停止、ChatGPT 授權與回答音訊路由。

音箱喚醒、音箱按鍵觸發與音箱麥克風目前仍需兩款裝置集中驗收，確認 Android 媒體事件或 GATT 通知及錄音輸入能力後再接入。Gemini 與 Claude 保留官方登入入口；只有供應商提供不需專案伺服器的官方用戶端授權流程後，才加入 App 內自動回答。
